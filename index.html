01 / CHARTER

立项决议

项目目标五大业务模块一体化

会员、活动、商城、大咖和 AI 生态在同一账号、订单与运营体系内交付。

技术策略复用交易底座，重建商会领域

CRMEB 承担账号、商品、订单、支付和后台权限；租户、会籍、好友、活动和预约由项目独立建模。

交付原则一次立项，全量开发

不拆成用后即弃的演示系统；发布会版先保证主链路可用，随后在同一代码基线上加固。

立项日：2026-07-17。G0 验收：2026-07-21，隔离运行、迁移、TenantContext、OpenAPI、前端基线、支付退款事件审计和自动门禁均通过。下一门禁：完成注册、L2 认证、L3/L4 会籍支付和幂等权益的 G1 垂直切片。

07 / GATES

开发门禁

  • 禁止直接修改 CRMEB 子模块；必须走 overlay 或独立服务。
  • 私域数据查询必须有 TenantContext，跨租户负向测试必须通过。
  • 支付、退款、积分、贡献值和分账采用追加账本与冲正。
  • 新增 API 同步提交路由、鉴权、错误码、OpenAPI 和 HTML 文档。
  • PR 合并前执行 scripts/check-g0-baseline.sh，不得带入子模块未提交修改。
