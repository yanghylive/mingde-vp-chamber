TenantContext CRMEB v6.0.0 装配说明

已实现并通过真实 CRMEB HTTP 内核验证。构建脚本将本目录复制到隔离运行副本的 app/chamber；CRMEB 子模块不接收业务修改。

运行端点

方法与路径租户要求用途
GET /chamber/health无应用存活检查，不解析租户，不主动查询数据库或 Redis。
GET /chamber/v1/bootstrap必须返回可信的 tenant/channel 上下文；来源为服务端 Host 映射或签名渠道入口。

环境变量

变量要求说明
CHAMBER_ENV生产建议显式设置production、local、development 或 test；默认 production。
CHAMBER_HOST_MAP_JSON使用域名识别时必填Host 到 tenant slug/channel code 的服务端映射，示例见下方。
CHAMBER_TENANT_SIGNING_SECRET使用签名入口时必填至少 32 字节，只从环境或密钥服务读取，不进入 Git。未配置时签名请求返回 503，Host 映射仍可用。
CHAMBER_TENANT_SIGNATURE_TTL可选签名时钟窗口，30-900 秒，默认 300。
CHAMBER_TENANT_REPLAY_PREFIX可选Redis nonce 键前缀，默认 chamber:tenant:nonce:。
CHAMBER_CORS_ALLOWED_ORIGINS跨域调用时必填逗号分隔的精确 http/https Origin；不接受通配符、路径或任意 Origin 回显。
CHAMBER_CORS_ALLOW_CREDENTIALS可选是否发送凭据许可头，默认 true；即使开启也必须命中精确 Origin 白名单。
CHAMBER_DEV_LOCALHOST_ENABLED仅本地显式设为 true 才增加 localhost/127.0.0.1/::1 映射。

CHAMBER_DEV_CHANNEL_CODE启用本地映射时必填必须对应同一租户的 ch_channel.code。

CRMEB 原有 MySQL 与 Redis 环境变量继续由平台配置负责。目录查询使用无前缀的 ch_tenant、ch_channel，不会拼成 eb_ch_*。

签名渠道入口

请求需要以下 Header：X-Chamber-Tenant、X-Chamber-Channel、X-Chamber-Timestamp、X-Chamber-Nonce、X-Chamber-Signature。签名是下列规范串的 HMAC-SHA256 小写十六进制值：

HTTP_METHOD
normalized_host_without_port
external_request_path
tenant_slug
channel_code
unix_timestamp
nonce

例如 bootstrap 的外部路径是 /chamber/v1/bootstrap。nonce 为 16-128 位 URL 安全字符；Redis 通过 Lua 原子 SET NX EX 占用 nonce，相同签名不能重放。

容器与路由

  • 所有数组响应包含顶层 request_id。合法的 X-Request-Id 与 X-Correlation-Id 分别透传；Request ID 无效或缺失时生成 32 位随机值，Correlation ID 无效或缺失时回落到 Request ID。
  • Chamber 使用独立 CORS 中间件，只回显精确白名单 Origin；未知 Origin 返回 403 cors_origin_denied，不会继承 CRMEB 的通配 CORS。允许两个 trace Header 和五个 X-Chamber-* 签名 Header，并向浏览器暴露两个 trace 响应 Header。
  • Redis 防重放不可用时签名入口失败关闭，返回 503 replay_guard_unavailable，不降级为可重放请求。
  • provider.php 懒加载数据库目录、签名校验器和 Redis 防重放实现，健康接口不依赖这些服务。
  • TenantContextMiddleware 将上下文写入当前 Request 和 ThinkPHP Container；响应结束后在 finally 中清理，兼容常驻进程。
  • 业务服务通过 app()->make(\app\chamber\tenancy\TenantContext::class) 读取上下文，资源查询后继续调用 assertTenant 或 assertScope。
  • 客户端提交的 tenant_id、channel_id 不参与解析。

反向代理必须覆盖并清洗 Host 和 X-Forwarded-Host，不能把任意客户端转发头原样交给 PHP。超级管理员跨租户操作仍需后续数据范围中间件与审计日志，不能靠修改 Header 实现。
