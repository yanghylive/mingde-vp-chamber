1. 范围与结论

chamber-openapi.yaml 是二开接口契约的版本库事实源。G0 两个操作、会员初始化、资料、附件、认证和管理审核，以及 G1-01D 会籍计划和结算共 15 个操作标记为 implemented；我的会籍查询仍为 1 个 planned 操作。

交付边界：planned 只表示契约已确定，不表示路由已上线。实现完成时必须在同一变更中加入路由、服务、测试，并把状态改为 implemented。前端不得根据中文 msg 分支。
运行时已对齐：用户端使用 CRMEB api Token，管理端使用 CRMEB Admin Token + 专用权限；身份后解析 TenantContext。资料、附件上传、认证提交和审核写操作进入主体域幂等，私有内容读取重新鉴权并禁止公共缓存。完整真实 HTTP 链路已通过。

实施、数据与生产边界见 G1 个人资料与毕业认证开发基线；后续会籍锁序见 G1 会员交易开发基线。

3. 统一响应与追踪

{
  "status": 200,
  "msg": "ok",
  "data": {},
  "request_id": "01K0N7G0V3X1VQ44R3GY2X6D1A"
}
  • status 必须与 HTTP 状态码一致；msg 只供人阅读；data 始终存在。
  • 调用方可传 X-Request-Id；服务端接受合法值，否则生成新值，并在响应头和正文 request_id 中返回同一值。
  • X-Correlation-Id 用于跨服务链路；未传时等于最终 request ID，响应必须回传。
  • 两个 ID 都是 8–128 位不透明字符串。日志、队列消息和下游 HTTP 调用必须继续传递 correlation ID。

4. 认证、租户上下文与错误码

G1 用户端操作由 Chamber 认证中间件调用 CRMEB UserAuthServices::parseToken 校验 Bearer Token，可信用户 ID 只取认证后上下文。管理审核操作使用 CRMEB Admin Bearer，并额外要求权限 chamber.graduate_verification.review。请求正文或查询参数中的 uid、member_id、tenant_id、channel_id 均不得参与身份判断。

租户从 Host 映射或签名渠道解析。客户端传入的普通 tenant_id/channel_id 永远不能作为权限依据。只要出现任意一个签名头，以下五个头必须全部提供：

X-Chamber-Tenant
X-Chamber-Channel
X-Chamber-Timestamp
X-Chamber-Nonce
X-Chamber-Signature
HTTP稳定 reason语义
400missing_context、invalid_input没有可信上下文，或请求上下文结构非法
401incomplete_signature、invalid_input、stale_signature、bad_signature、replayed_request签名集不完整、非法、过期、验签失败或重放
403unknown_tenant、conflicting_context、inactive_tenant、cors_origin_denied渠道不存在、Host 与签名冲突、租户停用或浏览器 Origin 未进入精确白名单
403 预留cross_tenant_access、cross_channel_access领域资源与 TenantContext 不同域；相关端点上线前必须完成异常映射
503signing_unavailable、replay_guard_unavailable服务端未配置签名密钥或 Redis 防重放不可用，签名入口失败关闭

跨域请求只允许 CHAMBER_CORS_ALLOWED_ORIGINS 中逗号分隔的精确 Origin。白名单不接受 * 或带路径地址；启用凭据时也不会回显任意 Origin。

幂等：G1 的 POST/PATCH 必须携带 Idempotency-Key。服务端用可信 tenant、稳定 operationId、认证主体类型/ID 和客户端键组成带版本的规范化元组，计算 SHA-256 后再写入幂等表；客户端原始键不得单独作为数据库身份。同作用域同键同请求返回原结果，同键不同规范化请求返回 409 idempotency_conflict。
协议版本：bootstrap 请求只提交 document_code、document_version 和接受决定，不接收内容哈希。服务端以 tenant-scoped、不可由客户端改写的协议注册表为事实源，解析当前正文并自行计算、保存 content_sha256；旧版本返回 409 consent_document_stale。

退款终态：admin_order_refund_success、渠道同步受理和 CRMEB 的 refund_status 只能产生 commerce.refund.processing.v1。余额事务提交、渠道查询成功或人工财务确认才允许产生 commerce.refund.completed.v1；部分退款必须携带稳定且唯一的 completion_id。

7. 本地静态验证

脚本仅使用 macOS 自带 Ruby/Psych，无需 npm、Composer 或网络：

ruby backend/custom/openapi/validate.rb

# 也可指定待验证文件
ruby backend/custom/openapi/validate.rb path/to/chamber-openapi.yaml

它会检查 YAML 重复键、本地 $ref、14 条路径与 16 个 operationId、85 个 Schema、15 implemented / 1 planned 状态、用户/管理 Bearer、租户头、幂等头、私有内容查询/响应头、统一 envelope、金额/时间/分页、商业事件和无 PII 约束，以及会员请求不得接收可信身份字段。它是项目治理校验，不代替完整 OpenAPI JSON Schema 校验器。

变更规则：破坏性变更必须提升 API 主版本；非破坏性字段扩展提升契约次版本；仅文案/示例修订提升补丁版本。
