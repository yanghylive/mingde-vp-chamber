用于固定上游源码假设，防止 CRMEB 子模块升级或人工改动后，商会二开仍按旧的支付、退款语义运行。

运行方式

脚本只读取本地源码和 Git 元数据，不访问网络，不修改 CRMEB 子模块，也不依赖第三方 Ruby Gem。

  • 0：全部锁定观察与 CRMEB v6.0.0 一致。
  • 1：至少一项源码语义发生漂移。
  • 2：文件、源码结构、Git 提交或标签预检失败。
注意：输出中的 MATCH 表示“已知现状仍存在”，不代表该实现安全。风险项匹配成功，恰恰说明二开保护层仍然必要。

检查边界

脚本按目标类的方法体提取并检查事件、状态写入顺序和渠道能力；业务层缺少退款查询消费则检查全部 app/**/*.php 调用点。执行前会验证目标文件存在、注释与字符串闭合、括号结构、子模块标签、提交号和已跟踪文件是否干净。

它是源码兼容哨兵，不替代支付沙箱、渠道回调、并发、故障注入和隐私合规测试。商会二开仍需通过原子状态迁移、支付事实表与 Outbox 解决上述风险。

文件范围：backend/custom/commerce。未修改项目主文档和 CRMEB 上游源码。
