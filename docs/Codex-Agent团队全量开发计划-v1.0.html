02 / TEAM TOPOLOGY

Agent 团队结构与权责

角色是工作槽，不是永久占用的固定身份。同时最多活跃 4 个 Agent；某条工作流进入等待时，该槽可切换到契约测试、安全或文档。

LEAD

Codex 主 Agent

拆解需求、分配任务、冻结共享契约、审查每个 diff、执行集成测试、管理 Git 提交、向用户报告。主 Agent 也负责 OrderContext、幂等、退款完成适配和跨域集成。

BACKEND

CRMEB 后端/数据 Agent

拥有 backend/custom：TenantContext、ch_* 迁移、会员、好友、活动、商品审核、结算、大咖、档期与预约。禁止直接修改 backend/crmeb。

FRONTEND

UniApp/管理端 Agent

拥有 frontend/custom：双品牌壳、五大用户模块、我的、创作者中心与 Vue2 运营后台。按“契约→Mock→真 API→异常状态→真机”交付。

AI / DELIVERY

AI 平台/测试/运维 Agent

拥有 ai-service、deployment 与对应测试：FastAPI、短期令牌、SSE、模型路由、RAG、工具、配额、审计、CI/CD、监控、压测与演练。

人工保留权：业务负责人确认会籍权益、价格、分账和内容；财务/安全负责人保管商户、生产密钥和上线签字。Agent 不能自行批准法律授权、真实付款、生产数据删除和公网发布。

03 / OPERATING PROTOCOL

主 Agent 如何带队执行

3.1 每个并行批次

  1. 主 Agent 先检查 Git 工作区和基线脚本，只从干净、可重现状态开始。
  2. 主 Agent 为每个执行 Agent 发送任务包：需求 ID、目标、允许修改目录、只读依赖、禁止项、测试和 DoD。
  3. Agent 只修改已分配的文件所有权；共享路由、迁移序号、OpenAPI、错误码和构建脚本由主 Agent 串行维护。
  4. Agent 交付时返回变更清单、行为说明、已运行测试、未覆盖风险和需要的契约变更。
  5. 主 Agent 逐个审查 diff，集成一个 Agent 的产物后才运行跨域测试；冲突不交给 Git 自动猜测。
  6. 主 Agent 统一提交 Git，更新任务状态和验收证据，再开始下一批。

3.2 并行纪律

规则实施触发停止
单文件单所有者一个批次中，任何文件只分配给一个 Agent。发现用户或其他 Agent 并发修改时暂停并重新读取。
WIP 限制每个执行 Agent 同时只有一个主任务，完成测试才领下一个。任务超出 1–2 小时可审查范围时再次拆分。
不使用未冻结契约前端/AI 先用版本化 Mock，不根据控制器名称猜测。返回字段、错误码或状态机未定义时不进入真接口联调。
当前任务内完成主 Agent 不把未完成工作假设为“后台会自动继续”。遇到外部凭据、业务决策或上线授权才向用户提升。

04 / CRITICAL PATH

不能靠并行跳过的关键路径

C0源码事件核验 + overlay 构建
C1迁移体系 + TenantContext
C2OpenAPI + 错误码 + 状态机
C3OrderContext + 幂等 + 账本
C4会籍支付垂直切片
C5活动/商城/预约复用交易骨架
C6真实退款冲正 + 故障注入 + RC
  • TenantContext 未通过跨租户负向测试前，任何私域 CRUD 不能合并。
  • OrderContext 未完成前，不允许会籍、票务、预约各自写一套支付回调。
  • 价格、积分、权益和结算规则在下单时冻结快照，不在支付后用当前配置反推。
  • OrderRefundCreateAfterListener 代表“提交退款申请”，只可冻结履约/待结算；只在真实退款完成后才撤销权益并写负向账本。
  • 零元报名可能不经支付回调，必须定义统一的业务完成事件。
可并行的工作：契约冻结后，前端 Mock、AI 网关、内容准备、安全用例和运维骨架可同时推进；好友模块不依赖支付，可插入支付凭据等待窗口。

8.1 AI 与性能专项

  • Gateway 自身开销 P95 ≤ 200ms；30 路并发流式会话 TTFT P95 ≤ 3s；工具查询 P95 ≤ 1.5s。
  • 知识库严格按 tenant_id + assistant_id + authorization_scope 过滤，跨租户检索零命中。

  • 外部模型不可用作 CRMEB 交易主链路的强依赖；模型、Redis 或向量库故障时不影响注册、支付、报名和预约。
