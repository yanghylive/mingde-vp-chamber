## 2. 待办清单（按优先级，全部需要你的权限）

### P0-1　轮换阿里云 AK/SK（安全，最高优先级，约 5 分钟）

**背景**：2026-10-05 会话中，域名 `uzhangai.vip` 与 `kaypal.cn` 的阿里云 AccessKeyId/Secret 被贴进聊天记录，可能已进入日志。**这对密钥能操作两个域名的 DNS/CDN，风险是域名被劫持到任意服务器。**

**操作**：
1. 登录阿里云控制台 → 访问管理 → AccessKey。
2. **禁用**（或直接删除）那两对 AccessKey。
3. 重新生成新的对。
4. 确认生效：解析 `md.kaypal.cn` 仍指向 `118.178.108.44`：
   ```bash
   dig +short md.kaypal.cn   # 期望 118.178.108.44
   ```
5. 新密钥不要提交进仓库；如需入库请用环境变量或密钥管理服务。

> 注意：本次交接**不需要**把新密钥给任何人。生产部署用的是 SSH（`root@118.178.108.44`），与阿里云 AK/SK 无关。

### P0-2　配置微信后台「隐私保护指引」（容易被忽略，驳回风险高）

**背景**：小程序登录使用了 `open-type="getPhoneNumber"` 收集手机号。2023-09 起微信要求：调用这类个人信息接口前，必须在公众平台配置《隐私保护指引》并声明收集用途，否则用户点授权会失败或被判 2.1。

**操作**：
1. 登录 mp.weixin.qq.com → 设置 → 用户隐私保护指引 → 填写。
2. 收集的个人信息至少勾选：**手机号**（用于微信一键登录绑定账号）。
3. 用途：账号注册与登录。
4. 第三方：如有共享给阿里云短信，需一并声明。
5. 配置完用真机重新点一次「微信授权手机号」，确认能正常拿到 code。

### 3.1 部署到生产（标准流程，务必照做）

```bash
# 0) 先备份（不可跳过）
ssh root@118.178.108.44 'cd /opt/mingde-vp-chamber && TS=$(date +%Y%m%d-%H%M%S) && \
  tar czf backups/chamber-predeploy-${TS}.tgz backend/custom/app/chamber backend/custom/database/migrations && \
  docker exec md_kaypal_mysql sh -lc "MYSQL_PWD=\$MYSQL_PASSWORD mysqldump -u \$MYSQL_USER \$MYSQL_DATABASE | gzip > /tmp/predb.sql.gz" && \
  docker cp md_kaypal_mysql:/tmp/predb.sql.gz backups/mysql/predb-${TS}.sql.gz && ls -lh backups/*predb*'

# 1) 只读对比：代码差异 + 路由差异
SYNC_PROD_HOST=root@118.178.108.44 ./scripts/sync-prod.sh diff
SYNC_PROD_HOST=root@118.178.108.44 ./scripts/sync-prod.sh routes   # 提审前必跑：列出生产缺失接口

# 2) 传代码（自动 prepare 运行副本 + 重启 php 清 opcache）
SYNC_PROD_HOST=root@118.178.108.44 ./scripts/sync-prod.sh push

# 3) 跑迁移（把迁移目录和执行器拷进容器后执行）
ssh root@118.178.108.44 'cd /opt/mingde-vp-chamber && \
  docker exec md_kaypal_php sh -lc "rm -rf /tmp/mig && mkdir -p /tmp/mig" && \
  docker cp backend/custom/database/migrations md_kaypal_php:/tmp/mig/migrations && \
  docker cp scripts/prod-migrate.php md_kaypal_php:/tmp/prod-migrate.php && \
  docker exec md_kaypal_php php /tmp/prod-migrate.php --dry-run && \   # 先看要执行什么
  docker exec md_kaypal_php php /tmp/prod-migrate.php'               # 再正式执行

# 4) 验证
for u in /chamber/health /chamber/v1/bootstrap /chamber/v1/events /chamber/v1/experts /chamber/v1/products /chamber/v1/coaching/today; do
```

**`prod-migrate.php` 的保护机制**（已在生产验证）：
- 已登记的迁移：只复验，FAIL 记 WARN **不阻塞**（生产有老数据漂移属正常）
- 未登记的新迁移：apply 后必须结构校验全 PASS，否则**立即中止**
- 切分 SQL 时跳过单引号内的分号（条件 DDL 内层含分号）

### 3.3 数据库约定

- 迁移文件三件套：`<version>_<name>.up.sql` / `.verify.sql` / `.down.sql`，版本号统一 **12 位**（如 `202610060001_backfill_...`）
- `up.sql` **必须可重复执行**：建表用 `CREATE TABLE IF NOT EXISTS`，加列用条件 DDL（`SET @ddl := IF(列不存在, 'ALTER...', 'DO 0')`）
- `verify.sql` 必须是标准格式：`SELECT 'name' AS check_name, IF(COUNT(*)=1,'PASS','FAIL') AS result, ...`，否则门禁的 `verify_migration_structure` 会因"无 PASS 产出"而失败
- 索引存在性检查用 `COUNT(DISTINCT index_name)`（`information_schema.statistics` 是每列一行）
- 本地执行：`./scripts/manage-local-database.sh migrate | verify | setup`
