1. 项目背景与立项依据

1.1 行业背景

中国高端商会、行业协会、校友会、私董会等"VP 级"人脉社群近年快速增长。这类组织的典型特征：

  • 客单价高：年费通常 ¥5,000-50,000，会员对品质和服务敏感
  • 关系深度优先：会员期待的不是"信息流"，而是"被精准匹配的人脉"
  • 活动密度高：沙龙、晚宴、参访、路演每月 4-10 场
  • 支付场景多元：会费、活动费、商城、大咖咨询费、AI 增值服务
  • 数据资产核心：会员画像、人脉图谱是组织最值钱的资产

1.2 痛点分析

痛点维度现状（人工 / 通用 SaaS）期望（理想状态）
会员管理Excel + 微信群，会费催缴手动在线会费、等级、续费提醒全自动化
活动运营接龙 + 现场签到纸质在线报名、扫码签到、限流、票务一站式
商城变现无独立商城，仅靠会费积分+现金混合的私域商城
大咖连接朋友圈、公众号单向大咖主页 + 付费预约 + AI 助手
AI 增值无AI 陪跑、AI 咨询、AI 工具调用

1.3 立项依据

市面现成方案存在以下问题：

方案 A（Discourse + 插件扩展）：Discourse Trust Level 是活跃度自动升降，无法映射"付费等级"。好友、L1-L4 等级、商城、活动报名均需要深度定制，论坛基因 ≠ 商会基因。

方案 B（fuint + bbs-go 双系统）：双系统数据同步复杂（会员状态、积分、订单需双向同步），运维成本翻倍，团队需同时掌握 Java + Go。

现成 SaaS（如知识星球、鲸会）：年费 ¥3-10 万，但定制性差、数据不私有、无法接入自有 AI 大模型，无法沉淀核心资产。

本方案核心主张：采用 Apache-2.0 / GPLv2 纯开源免费组件 自建，技术风险可控、首年综合成本 ¥9.75-13.3 万（含人力），有收入后再升级到 CRMEB 商业版（平滑迁移路径已规划）。

7.2 关键选型理由

为什么选 CRMEB 开源版？

  • ✅ 唯一在 PHP 生态提供"付费会员 + 等级会员 + 商城 + 分销"四件套的开源项目
  • ✅ Apache-2.0 协议，明确允许免费商用
  • ✅ 国内社区活跃、文档中文、招 PHP 工程师容易
  • ✅ 平滑升级路径：业务跑通后升级到商业版（¥1-3 万/年）无需重构

为什么不用 Discourse 做会员主库？

Discourse Trust Level 是活跃度自动升降（新人→基础→会员→活跃→领袖），无法映射"花钱买等级"。原方案将 Trust Level 对应 L1-L4 是业务理解错误。本方案将会员主库放在 CRMEB，Discourse 仅承担社区/活动补充。

为什么选 LobeChat？

  • Apache-2.0，不改源码可直接商用
  • UI 美观、支持多模型（DeepSeek/通义/文心）
  • Plugin 生态丰富（联网、计算、绘图）
  • 注意：二次开发并分发衍生作品需购买商业许可（自用 OK）

8. 系统架构设计

8.1 整体架构

┌─────────────────────────────────────────────────────┐ │ Client Layer │ │ ├── UniApp (小程序 / H5) │ │ ├── LobeChat Web (AI 对话) │ │ └── Discourse Web (社区/活动补充) │ └──────────────────┬──────────────────────────────────┘ ↓ ┌─────────────────────────────────────────────────────┐ │ Nginx (HTTPS / 反向代理 / 限流) │ └──────────────────┬──────────────────────────────────┘ ↓ ┌──────────┬──────────────────┬──────────────────┐ │ CRMEB │ Discourse │ AI Service │ │ (PHP) │ (Ruby) │ (FastAPI) │ │ 主业务 │ 社区/活动 │ AI 网关 │ └────┬─────┴────────┬─────────┴────────┬─────────┘ │ │ │ ↓ ↓ ↓ ┌─────────────────────────────────────────────────────┐ │ Data Layer │ │ MySQL (CRMEB) + PostgreSQL (Discourse) │ │ Redis (缓存/队列) + MinIO (对象存储) │ └─────────────────────────────────────────────────────┘

8.2 SSO 单点登录流程

  1. 用户从 UniApp 小程序登录，CRMEB 颁发 JWT Token
  2. 访问 Discourse 时，CRMEB 网关验证 Token → 调用 Discourse API 创建/同步用户 → 颁发 Discourse Session Cookie
  3. 访问 LobeChat 时，AI Service 验证 Token → 返回 LobeChat 临时访问凭证
  4. 退出登录时，CRMEB 通知 Discourse / LobeChat 清除会话

8.3 数据流

  • 会员主数据：CRMEB（Source of Truth）→ 同步至 Discourse / AI Service
  • 积分变动：CRMEB 触发 → 异步通知 AI Service 同步 → Redis 缓存
  • 订单数据：CRMEB 写入 MySQL → OSS 存储电子凭证 → AI Service 用于推荐
  • 对话历史：AI Service 写入 PG → 用于大咖 AI 分身训练

11. 风险评估与应对策略

风险等级应对策略
Discourse Ruby 开发者稀缺🟡 中Discourse 仅承担社区/活动，主业务用 PHP。需要 Ruby 改动时外包或培训现有团队
CRMEB 开源版功能受限🟡 中不含 SCRM/直播/多门店/三级分销。需求出现时升级商业版（¥1-3 万/年）
Discourse 不支持小程序原生🟡 中小程序端用 H5 容器（WebView）包裹 Discourse，已验证可行
SSO 单点登录开发🟢 低预留 1 周开发时间，参考 Discourse OAuth 文档
小程序审核被拒🟡 中"社交-社区"类目审核严格。建议先用 H5 跑通，小程序作为补充渠道
LobeChat 商用条款🟢 低不改源码、不分发衍生作品的前提下可直接商用。自用场景无风险
AI 成本失控🟡 中设置用户 Token 配额，超出按量付费。监控异常调用
团队流动🟡 中完善文档（CI/CD、部署手册、Runbook），关键知识双人备份
