1. 已接受决策

ADR决定原因实施约束
ADR-001CRMEB v6.0.0 固定为 Git 子模块，上游源码只读保留清晰升级边界，避免二开与官方代码混杂业务代码进入 backend/custom；构建时复制到隔离运行区
ADR-002一个业务主库、共享表结构、后端强制租户上下文双品牌共享交易和 AI 能力，避免复制系统后产生数据分叉私域表必须有 tenant_id；客户端不能决定最终租户范围
ADR-003CRMEB 继续承载账号、商品、订单、支付；商会语义使用 ch_ 领域表复用成熟交易链路，同时避免误用付费会员、秒杀活动、推荐关系和事业部会籍、活动、好友、人物角色、贡献值均不得挤入含义不同的 eb_ 字段
ADR-004本地和发布构建使用可再生运行副本安装器会写入 .env、锁文件和运行目录，直接挂载子模块会污染上游状态.build-workspace 与本地数据不入库；每次装配检查 Overlay 冲突
ADR-005密钥、真实会员资料和生产备份不进入仓库仓库私有不等于可以保存敏感数据只提交示例配置；本地凭据写入被忽略目录；生产使用密钥管理服务
ADR-006商会 API 使用独立 ThinkPHP chamber 应用路由、异常、租户中间件和 CORS 可独立治理，同时仍可复用 CRMEB 容器、数据库和基础设施业务路由位于 app/chamber；CRMEB 原 api/adminapi 不承载商会领域语义
ADR-007CRMEB 的 admin_order_refund_success 只作为 processing 信号它在渠道请求未抛异常后立即发出；源码没有退款回调消费或业务层查询对账，不能证明外部资金完成仅余额事务提交、渠道查询成功或人工财务确认可产生 commerce.refund.completed.v1
ADR-008Host 映射与 HMAC 签名渠道是租户上下文的可信入口普通 tenant_id 可伪造；两个可信来源可以服务 H5、小程序和渠道入口两者同时出现必须同域，否则拒绝；签名带时间窗和 Redis nonce；登录身份只能在此上下文内继续收窄权限
ADR-009交易事实先落持久化 inbox，再异步执行业务效果支付事件覆盖不全且并发回调非原子；订单已写 paid 后事件仍可能丢失数据库唯一键做幂等仲裁；CRMEB 事件只作加速，订单/退款扫描负责补发；同键不同 payload 冲突告警
