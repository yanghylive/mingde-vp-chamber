1. 目录边界

目录所有者内容规则
backend/crmebCRMEB 上游官方 v6.0.0 完整源码只更新子模块指针，日常开发不直接改动。
backend/custom/app/chamber项目后端Controller/Services/Dao/Model/Listener/Job保持 CRMEB 分层；领域表统一 ch_ 前缀。
backend/custom/database/migrations项目后端可追踪 SQL 迁移只追加版本，不编辑 CRMEB 安装 SQL。
frontend/custom/uniapp移动端页面、组件、API、资源 overlayVue2/UniApp 风格，禁止混入 Vue3 专用语法。
frontend/custom/admin管理端Vue2/Element UI 页面与 API菜单、API 权限和页面必须一起提交。
ai-serviceAI 平台FastAPI 网关、RAG、工具、配额和审计不直连 CRMEB 数据库，只调用受控 API。
deploymentDevOpsCompose/Nginx/CI/发布 manifest不提交密钥和真实环境配置。

2. 功能开发流程

  1. 从 PRD 需求 ID 开始，确定验收条件和影响范围。
  2. 在 CRMEB v6.0.0 中定位同类路由、Controller、Services、Dao/Model 和事件。
  3. 对照复用矩阵，明确“直接复用 / 扩展 / 新建 / 禁用误用”。
  4. 先提交数据迁移、API 契约和失败用例，再实现服务与页面。
  5. 在干净 CRMEB 工作副本中应用 overlay，构建并执行单元/API/E2E 测试。
  6. 更新 HTML 文档和 release manifest，提交 PR 评审。

3. Git 约定

  • main 始终可发布；功能分支使用 feature/<req-id>-<name>。
  • 提交使用 feat:、fix:、docs:、test:、chore:。
  • 上游升级使用 chore/crmeb-upgrade-x.y.z，单独审查子模块和 SQL 差异。
  • 仓库默认私有；不得提交 .env、私钥、会员资料、上传文件和生产备份。

4. 构建产物

1. git submodule update --init --recursive
2. verify CRMEB SHA and clean submodule
3. copy backend/crmeb to an isolated build workspace
4. apply backend/custom and frontend/custom overlays
5. run database/API/frontend tests
6. build CRMEB, Admin, UniApp and AI images/packages
7. emit release-manifest.json with every source SHA

overlay 冲突必须终止构建，不得静默覆盖上游新文件。生产部署使用已构建产物，不在服务器直接 git pull 或运行 CRMEB 后台在线升级。

5. Definition of Done

  • 需求 ID、代码、数据迁移、测试和文档可相互追踪。
  • 子模块指针正确且无未提交修改。
  • 租户越权、重放、支付回调和退款冲正测试通过。
  • 空库与升级库迁移均通过。
  • 监控、日志、告警和回滚说明已更新。
