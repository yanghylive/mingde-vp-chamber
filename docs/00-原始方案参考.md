## 三、推荐选择：方案A（Discourse）

**理由：**
1. **一个系统覆盖70%需求**，不需要维护多套系统
2. **会员、积分、等级、搜索、好友全是原生功能**，开箱即用
3. **插件生态成熟**：Calendar、Gamification、Checklist等都有现成插件
4. **商城和AI是增量开发**，通过API/嵌入方式对接，不影响主系统稳定性
5. **Discourse社区43k Stars**，长期维护有保障，遇到问题容易找到解决方案

## 四、方案A落地路线图

### 第一阶段：基础搭建（1-2周）

```
1. 服务器准备
   - 推荐配置：2核4G起步，50G SSD
   - 系统：Ubuntu 22.04
   - Docker + Docker Compose

2. Discourse部署
   - 使用官方discourse_docker
   - 配置SMTP邮件（活动通知、签到确认）
   - 配置OSS/MinIO存储（图片、视频）

3. 基础配置
   - 自定义Trust Level映射L1-L4
   - 创建分类：个人成长/事业行业/公益慈善
   - 配置用户自定义字段（公司、行业、规模、主营业务等）
   - 配置Gamification积分规则
```

### 第二阶段：活动中心（2-3周）

```
1. 安装Calendar插件
   - 活动日历视图展示
   - 活动时间/地点/地图导航

2. 活动报名限制
   - 基于Group权限控制（L1-L4不同等级看到不同活动）
   - 费用设置：免费/积分/现金/混合
   - 报名名额限制

3. 扫码签到
   - 每个活动生成唯一QR码
   - 签到后自动发放积分（通过Webhook触发）

4. 活动分类标签
   - 个人成长、事业行业、公益慈善三大Tag
   - 按分类筛选和展示
```

### 第三阶段：商城对接（2-3周）

```
方案1（轻量）：嵌入ShopXO
- 独立部署ShopXO商城
- Discourse通过iframe或API跳转
- 积分通过API同步（Discourse积分→ShopXO积分）

方案2（深度集成）：Discourse + WooCommerce
- WordPress + WooCommerce作为商城后端
- Discourse通过WP REST API对接
- 统一用户登录（SSO）

积分+现金混合支付：
- 积分抵扣规则在商城端实现
- 调用Discourse API扣减积分
- 微信支付走商城原生通道
```

### 第四阶段：大咖主页 + AI（2周）

```
1. 大咖主页

   - 展示：头像/简介/擅长领域/预约价格

3. 付费预约
   - 线上：AI对话次数/时长用积分购买
   - 线下：通过活动模块发布一对一预约活动
```

### 第五阶段：AI生态模块（1-2周）

## 八、风险与建议

1. **Discourse是Ruby on Rails项目**，如果需要深度定制，需要Ruby开发能力
2. **小程序端需要额外开发**，Discourse原生不提供小程序，需要通过UniApp封装API
3. **积分+现金混合支付**是最复杂的模块，建议在商城侧实现，Discourse只做积分扣减
4. **大咖AI对话框**的"一对一付费"逻辑，建议通过活动模块+积分支付实现，而非独立支付系统
5. **建议先跑通MVP**（会员+活动+积分+社区），商城和AI作为二期
