## 一、7 项硬门禁（S0 · 阻断级）

### G1. 金额整数分 + 尾差分摊
- [ ] 所有金额使用**整数分**运算，禁止浮点数（含 bcmath 校验）
- [ ] 4:4:2 比例总和**严格 = 100%**（不能沿用「总和 ≤ 100%」的宽松校验）
- [ ] 尾差**分摊到最后一个接收方**（如 99 分 → 40 / 39 / 20）
- [ ] 手续费单独建模：明确「先扣后分」还是「平台留存承担」，页面显示金额 == 汇付实际金额
- [ ] 金额只能从**已支付的真实业务订单**读取，禁止信任客户端传入金额

### G2. 回调字段级校验
- [ ] `HuifuSigner::verify()` 验签通过（`openssl_verify === 1`）
- [ ] 校验**商户订单号、金额、商户号、币种、时间戳**（防重放，结合租户/状态）
- [ ] canonical 原串构造规则（字段排序/过滤/拼接）严格按官方合同实现
- [ ] 回调公钥**绑定证书序列号 serial_no**，防止换钥伪造

### G3. 幂等
- [ ] 重复回调只产生**一个**本地支付事实（DB 唯一约束 + 状态机）
- [ ] 分账请求幂等键 = **本地分账单号**
- [ ] `paid` 状态标记幂等（`created → pending → paid/closed/unknown`）

### G4. 接收方 huifu_id 白名单
- [ ] 只接受**已登记**的三个接收方 `huifu_id`
- [ ] **禁止前端传收款人名称/账号**（只传角色/规则 ID）
- [ ] 接收方 KYC/实名/账户状态在下单前校验

### G5. unknown 状态分类与不盲重试
- [ ] 区分 `unknown` / `processing` / `success` / `failed` 状态
- [ ] `unknown` **禁止盲目重提**，必须先查单
- [ ] 只有确认汇付「未受理」才允许重试
- [ ] 人工对账/重试通道 + 完整审计日志

### G6. HUIFU_LIVE gate
- [ ] `HUIFU_LIVE=false` 时**拒绝真实交易**（feature flag 默认关闭）
- [ ] 测试环境 / 生产环境严格隔离（baseUrl、密钥、serial_no 分套）

### G7. 证书 / 密钥生命周期
- [ ] 请求签名 + 回调验签双通道齐全
- [ ] 公钥轮换流程（双密钥共存灰度 + serial_no 切换）
- [ ] 请求幂等键（outbox 写入后调用，防重复下单）
- [ ] 重试 / 限频 / 退避策略明确

## 二、上线验收标准（最终 gate，逐项留证）

对照 `HUIFU-三方分账接入方案.md` 第 9 节，上线前必须逐项通过：

- [ ] 一笔测试订单支付金额与汇付订单金额一致
- [ ] 支付通知重复 10 次只产生一个本地支付事实（G3）
- [ ] 100.00 元准确分成 40.00 / 40.00 / 20.00，汇付三方账单可核对（G1）
- [ ] 支付通知丢失时，主动查单能补齐状态（G2/G5）
- [ ] 分账请求超时**不会**重复分账（G3/G5）
- [ ] 分账受理但未最终成功时，不显示「已完成」（G5）
- [ ] 分账前 / 分账后全额 / 部分退款均能收敛
- [ ] 接收方 / KYC / 比例不满足时，支付前阻断（G4）
- [ ] 生产密钥、原始回调、身份证/银行卡等敏感信息不出现在日志
- [ ] `scripts/check-project.sh`、OpenAPI 校验、Chamber HTTP/DB acceptance 全部通过
