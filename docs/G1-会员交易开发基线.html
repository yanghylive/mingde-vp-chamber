2. CRMEB 源码假设修正

原假设源码事实确定方案
监听 UserRegisterListener 即可创建租户会员事件没有 TenantContext，且既有用户绑定推广关系时也会触发；事件本身不耐久在受保护 Chamber API 首次访问时，以可信 tenant + CRMEB uid 幂等惰性创建
OrderCreateAfterListener 可与订单原子写 OrderContextCRMEB 订单事务提交后才触发该事件会籍下单编排器先建 nullable-order Context，再建 CRMEB 订单并绑定；补扫任务修复提交间隙
支付成功监听器可直接开权益现有 G0 只把统一商业事实写入 inbox，尚无领域消费者消费者在同库事务内锁 inbox/context/order/member/term，创建唯一期限并标记事件完成
安全边界：Chamber CrmebAuthTokenMiddleware 严格解析 Bearer Token，并调用 CRMEB UserAuthServices::parseToken 验证真实 api Token。受保护路由固定先完成 Auth，再解析 Tenant；用户身份只取认证后的上下文，租户和渠道只取 TenantContext。正文、查询和路径中的 uid、member_id、tenant_id、channel_id 一律不可信。

3. 第一条纵向闭环

CRMEB api Token                           [G1-01B 完成]
  -> AuthenticatedUserContext
  -> TenantContext                       [Auth 先于 Tenant]
  -> 幂等创建 L1 member + profile + invite code
  -> 服务端解析协议版本并追加接受证据       [G1-01B 完成]
  -> 提交毕业生认证
  -> 运营审批为 L2
  -> 查询当前渠道 L3/L4 plan
  -> 创建 OrderContext（先 creating，后绑定 CRMEB order）
  -> CRMEB 支付/零元完成事实进入 commerce inbox
  -> 同库事务创建唯一 membership term + grant effect
  -> 从有效期限重算 member tier
  -> 期限到期时投影回 L2

L3 默认 1000.00 CNY/年，L4 默认 5000.00 CNY/年，必须先通过 L2。L3 升 L4 购买完整 L4 计划，不自动按天补差价；有效 L4 期间拒绝购买 L3。

4. 数据事实

表职责关键约束
ch_membership_plan租户渠道的 L3/L4 价格、期限、商品映射和政策tenant + channel + code/tier 唯一；历史订单只读快照
ch_order_contextCRMEB 订单与领域业务唯一绑定order_pk 全局唯一且绑定前可 NULL；身份、归属和快照不可改
ch_membership_term每个可信完成订单对应一段独立会籍期限context 与 grant event 幂等唯一；使用半开区间 [start,end)
ch_membership_term_effect追加记录授予、退款和人工调整effect key 同键同 hash 重放，异 hash 冲突；无软删除
ch_member_consent追加记录协议接受/撤回证据不保存原始 IP 或 User-Agent，只保存加盐摘要
ch_tenant_member当前等级与认证的可重算投影tenant + uid、tenant + invite code 唯一；首次归因锁定
ch_graduate_verification不可变认证申请历史nullable current_slot 唯一键阻止同会员多个当前申请

ch_tenant_member.tier 与 tier_expire_time 不是财务事实源。支付、退款、认证撤销、重新认证和到期任务都必须锁会员行并从期限事实重新投影。

协议版本信任边界：document_code + document_version 必须在服务端维护的 tenant-scoped 协议注册表中解析；客户端不提交、也不能指定 content_sha256。服务端只接受当前有效版本，并根据受控正文计算和保存 SHA-256；旧版本提交返回 409 consent_document_stale。

7. 幂等、事务与锁序

inbox
  -> ch_order_context
  -> eb_store_order
  -> ch_tenant_member
  -> ch_membership_term
  • term、effect、member 投影与 inbox processed 必须在同一个数据库事务提交。
  • 两个并发续费事件依靠 member 行锁串行；后一个在获得锁后重新计算开始时间。
  • 同支付事件重放 10 次只允许 1 个 term 和 1 个 grant effect；同一 term 的退款 completion_id 跨 partial/full effect 类型只能入账一次。
  • HTTP 幂等内部键必须由版本号、可信 tenant、operationId、认证主体类型/ID 和客户端键规范化后计算 SHA-256；不得直接持久化客户端原始键作为唯一身份。
  • 订单 tenant、channel、uid、金额、币种、状态或 Context 任一不一致时失败关闭，进入人工核验，不静默开通。
  • MySQL 必须启用 STRICT_TRANS_TABLES 或 STRICT_ALL_TABLES，防止负数和越界金额被静默截断；服务仍必须校验 refunded ≤ paid 等跨字段关系。
  • L3 升 L4 时保留原 L3 term；L4 全额退款后可自动回落到仍有效的 L3。
