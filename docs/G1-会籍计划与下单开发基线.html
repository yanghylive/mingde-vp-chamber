2. 端到端链路

CRMEB api Bearer Token
  -> CrmebAuthTokenMiddleware
  -> TenantContextMiddleware
  -> 当前渠道会员与认证状态
  -> 当前渠道 MembershipPlan 快照
  -> 预留 checkout 幂等记录

3. 数据与不变量

事实约束用途
ch_membership_plantenant + channel + plan code/tier 唯一；业务价格、期限和 CRMEB 商品映射由服务端维护形成不可变下单快照
eb_store_order.unique等于服务端生成的确定性 checkout key，数据库全局唯一抵抗锁租约过期和并发重复建单
ch_order_context.context_no与 CRMEB unique 一致；order_pk、idempotency_record_id 均唯一把 CRMEB 订单绑定到唯一会籍业务上下文
ch_idempotency_record同可信主体和 Key 的请求哈希不可改变；结果用 AES-256-GCM 密封稳定重放响应且不泄露原始客户端 Key

迁移 202607250004_link_order_context_idempotency 为 OrderContext 增加 nullable 幂等记录外键和唯一索引，202607250005_register_membership_repair_timer 注册每分钟缺口补扫任务，共新增 6 项结构复验。数据库仍为 180 张表，其中 CRMEB 157 张、Chamber 领域表 22 张、迁移登记表 1 张；全部迁移共 437 项复验，G0 165 项、G1 272 项。

4. 订单安全边界

  • 会籍商品必须是可售、未删除的虚拟商品和有效 SKU；购买数量固定为 1。
  • 订单 pay_type 必须为 weixin，支付金额必须等于计划金额，优惠、积分抵扣、邮费、赠送积分和五类佣金字段必须为 0；会籍商品标记 is_sub=1，不进入 CRMEB 推广分佣。
  • 购物车行、下单确认数据、最终订单和 OrderContext 必须共同匹配同一计划快照。
  • 原生 CRMEB cart/confirm/create/again 入口拒绝会籍商品；订单列表/详情/收银、订单商品、退款商品、购物车统计与删除等读取/操作入口均拒绝会籍单；原生订单取货流程对会籍订单跳过积分、经验、佣金和后置事件副作用。
  • 公开 API 由 app/api/provider.php 装饰，根 HTTP/queue/timer/CLI 由 app/provider.php 绑定订单、订单商品、退款和收货守卫；可信网关的私有缓存/持久化校验走 DAO，不把守卫降级成客户端约定。
  • 订单状态通过网关映射为稳定的 pending、paid、cancelled、refunding、partially_refunded 或 refunded，不把 CRMEB 内部状态直接泄露到 Chamber 契约。
  • 重放前重新校验当前用户、会员状态、租户、渠道和真实订单；旧成功响应不能绕过停用或跨渠道限制。
  • 补扫只处理已存在的确定性订单，按记录更新时间、重试次数和上下文 ID 公平排序；每次最多处理 50 条并记录日志。
